# 開発計画 — PanoramaNavis

Navisworks上の指定地点から360度パノラマ画像を生成するアドインの開発計画。

## ゴール

> Navisworksを持たない関係者（操業・保全・品質・承認者）に対して、
> 「その場所に立ったときの視界」をブラウザだけで共有できるようにする。

最終的には、設計モデルのパノラマと現場360度写真を同一座標で切り替える
「設計空間と現実空間を接続する定点観測基盤」を目指す。ただし各フェーズは独立して価値が出るよう構成する。

## 検証チェックリスト（Phase 1で実機確認する事項）

Navisworks APIはLinux上で検証できないため、以下を実機で確認する。
各項目は `ARCHITECTURE.md` の「API検証状況」と対応。

- [ ] `Viewpoint.HeightField` が垂直画角（ラジアン）として機能するか
- [ ] `Viewpoint.AspectRatio` の有無と、出力画像アスペクトとの関係
- [ ] `AlignDirection` → `AlignUp` の順序で6方向すべて意図通りに向くか（特に真上・真下）
- [ ] `lcodpimage` のオプション名一覧（初回実行時に診断ログへ出力される）
- [ ] 出力画像サイズが `export.image.width/height` に従うか、画角が幅高さ比に追従しないか
- [ ] JPEG/PNGフォーマット指定子（`lcodpexpng` 等）の正確な値
- [ ] 大きいモデルでの6面キャプチャ時間（実用に耐えるか）
- [ ] Near Clip による近接形状の欠け具合

## リスクと対応

| リスク | 影響 | 対応 |
|---|---|---|
| 画角が正確に90°にならない | 継ぎ目にズレ・二重像 | 検証用グリッドモデルで誤差測定。必要ならオーバーラップ撮影（>90°）＋クロップに切替（Coreは面画角パラメータ化済み） |
| 上下面のロール角ズレ | 天地の継ぎ目が回転 | 面ごとのUpベクトル規約を単一ソース（`CubeOrientation`）で管理し、実機で天地マーカー付きモデルにより検証 |
| カメラが部材内部に入る | 真っ黒・裏面が映る | Phase 2で距離判定と自動補正。PoCでは注意書きとリトライで運用 |
| レンダリング完了前にキャプチャされる | 面ごとに描画状態が異なる | 各面キャプチャを同期実行し、必要なら描画完了待ちを挿入 |
| Navisworksの.NET 8移行 | ビルド不可 | csprojはSDKスタイル。`TargetFramework` 変更のみで追従可能な構成にしてある |
| COM API廃止・変更 | 画像出力不可 | 画像出力は `ViewExporter` に隔離。代替手段（画面キャプチャ等）に差し替え可能な構造 |
